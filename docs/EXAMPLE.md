# 情境应用示例

下面是假设情境，由编辑示范如何使用检索结果，不是纳瓦尔说过的话，也不是通过某个模型 API 实测生成的回复。

**问题**：我有后端开发经验，想做一个开源工具。看到 AI 工具很多，不知道应该跟热点还是找自己熟悉的问题。时间有限，怎样决定？

**基于资料的分析**：

纳瓦尔在讨论专长时，将真实兴趣与已有能力联系起来。先从你已经反复解决的问题中寻找候选方向，能让这个原则与具体经历发生联系。[naval-e-specific](https://nav.al/specific-knowledge)

他在讨论产品杠杆时强调软件和内容能够复制分发。筛选项目时可以进一步检查：一个问题是否反复出现，做成软件后是否能让更多人独立使用。[naval-e-leverage](https://nav.al/product-media)

**应用到这个假设情境的下一步**：

1. 列出最近三次让你重复花时间的开发问题，以及现有解决办法。
2. 找到遇到同一问题的人，确认他们实际怎样处理；记录已有替代方案与切换成本。
3. 选一个能在有限时间内交付的小范围，观察别人是否独立使用、是否再次使用，以及维护需要多少时间。

这三个步骤是编辑的实践建议。引用资料没有给出用户的时间预算、目标用户或商业目标，也不能证明任何项目会成功。是否继续投入，应由实际需求与使用反馈决定。

可以用以下命令取出这个情境的依据包：

```bash
open-mentor context --person naval '我有后端开发经验，想做一个开源软件产品，怎么选择方向？'
```

## 孙宇晨：第一个 100w

**原问题**：帮我用 OpenMentor 问问孙宇晨，怎么赚自己的第一个 100w？

**示范回答**：基于孙宇晨已收录的公开资料，可以把这个目标拆成“客户需求、首次付费、稳定交付、重复成交”的验证过程。这里先不假定 100w 的币种、达成期限或计算口径。

1. **找到具体客户愿意付费解决的阻碍。** Alan 采访中，他把商业机会的判断落到能否为客户创造价值。应用到这个问题，可以先在熟悉的领域找一个反复发生、目前处理很麻烦的需求。[原片 00:35:32](https://www.youtube.com/watch?v=0Z-vhBvBmUY&t=2132)
2. **用小范围交付验证，而后增加投入。** 2015 年澎湃记者将其方法归纳为降低失败成本。应用上，可以先交付最小范围，观察是否有真实使用与付费，再决定继续还是调整。[原采访；此处为记者归纳](https://www.thepaper.cn/newsDetail_forward_1413224)
3. **把用户获得的改善与自己的收益分别算清楚。** 他在央视采访中从费用、速度等业务摩擦解释产品出发点。这里可以进一步记录交付成本、实际净收入与再次购买的原因。[央视采访](https://news.cntv.cn/2015/05/08/ARTI1431072425139748.shtml)

**可逆的下一步（编辑推演）**：选择一个熟悉的问题，与实际遇到问题的人交流，做一个小范围的付费试验，并预先约定时间和成本上限。如果无人愿意使用或付费，先复核需求和交付，不依据名人观点继续加大投入。

还需要确认：100w 指营业额、累计税后收入、利润还是净资产？希望多久达成？已经具备哪些技能、客户渠道和可投入资源？这些信息会改变具体路线。

以上是对当前问题的应用推演，不是孙宇晨本人回复，也不是他对金额、收益或期限的承诺。
