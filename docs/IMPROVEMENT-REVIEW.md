## 实现后复查发现及修复

1. `请用巴菲特的知识库分析赚钱，孙宇晨只作背景参考` 原先错误使用孙宇晨。路由现在先核对明确请求的导师，返回 `requested_person_unavailable`。
2. `不要用孙宇晨，用纳瓦尔……` 原先被当作多人歧义。现在识别常见否定指定，自动选择时也排除相应人物。明确正向指定优先于旁带姓名；真正的多人请求仍需选择。
3. `那我应该先做哪一步` 原先凭“先做”匹配工程原则。现在返回 `needs_context`；提供原问题后按 situation 检索，并将用户背景与人物证据分开。
4. 追加探针发现否定调用中的“知识库”等字样仍会影响自动排名。现在逐段剥离已知人物的调用前缀，保留原始问题，并覆盖并列否定与显式 person 覆盖原句姓名的追问。
5. `state.json` 为数组、null、非法状态或日期时，原先可能抛出未处理异常。现在统一校验并抛出 StateError，HTTP 映射为 503，不改写损坏文件。
6. 原实现先判断可用性，再重复读取来源并组装证据；更新恰好发生在两次读取之间时，引用可能标为可用但来源显示 changed。现在依据同一次读到的来源记录判断并组装证据，检索直接检查该证据的 eligible 字段。回归测试在读取之间模拟版本变化。

`.venv/bin/python -m unittest discover -s tests -v`：**57 项测试通过**，其中场景测试包含 **80 个输入**。覆盖七位人物、金额与非金额问法、无关主题、追问、输入校验、来源停用、机器转写待核隔离、更新恢复，以及真实 CLI / HTTP / MCP 调用。

复查后未发现当前验证范围内尚未修复的阻塞问题。没有把有限用例通过当作任意自然语言或任意调用模型都正确的保证。

## 保留边界

- 人物解析、追问识别和主题扩展是公开的有限规则；不提供通用语义理解。复杂歧义可显式传 person，并把清晰问题与 situation 分开。
- OpenMentor 返回依据与编辑应用，实际情境回答由调用方 AI 生成。引用证明公开表达，不能证明观点必然正确或承诺收益。
- 工具不保存聊天历史，也未自动向当前客户端登记 MCP。后续调用需传入必要背景与希望沿用的 person。
- 来源状态是读取时的观测，不保证远端页面在回复后不变；网页检查和版本接纳需要实际执行，不是后台自动监控。
- Alan 与 William 采访全文仍是机器转写待核稿。仅已逐片段核对的条目可用于引用，全文未升级成已核验知识；本轮没有扩大人物语料。
