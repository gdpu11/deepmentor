# 资料规范与复核

## 一个条目必须能沿证据回去

知识包位于 `deepmentor/data/people/*.json`，由包内 `data/pack.schema.json` 约束。

关系为 `person -> principle -> evidence -> source`。ID 在全库唯一，引用不得跨到别的人物。发布者、原始资料地址和实际读取的页面地址分开记录。

- `source.authority`：`first_party` 本人发布的文章或署名信；`publisher` 原采访/讲话发布者，或可确认作者署名原作的出版方；`compilation` 编者叙述或未回查原表达的选编；`secondary` 其他整理。
- `evidence.verification.status`：`reviewed`、`pending`、`disputed`、`retracted`。
- `origin_verified`：是否实际核对过原发布文字或原始音视频。第三方转写、书籍选编不能仅凭其存在而设置为 true。

书籍形式本身不决定原始性。出版方直接提供、可确认作者归属的署名书面原作，可以核验该出版文字版本；仍要区分编者叙述、他人引语和作者正文。例如芒格2005年亲自修订的《误判心理学》合成书面稿，由 Stripe Press 提供，核对的是书面版本，不能说成某次实际演讲逐字稿。仅找到书摘、选编或第三方机器稿，不满足这个条件。

- `reviewer` 必须明确填写。AI 辅助检查如实标注，不能冒充人工审稿。
- `locator`：可核对的标题、时间戳或具体帖子定位。没有确认的时间戳不填猜测值。
- `application`：编辑提出的应用问题、步骤和限制，始终与人物原话分开。

原发布者的画内字幕可以作为可定位的原发布文字检查；核验记录须写明是字幕/上下文检查还是逐句听辨。`source.review.status=reviewed` 只覆盖条目引用且明确记录的范围，不表示整场访谈或机器全文都已人工审定。原文表达已核对也不等于事实正确或方法有效。

默认指导只使用已审阅、原始表达已核对、来源处于已接纳状态的证据。用户明确允许时可以使用已审阅的二手资料，但保留实际发布者与原话尚未核对的标记。

## 复核不是检查一句话能不能搜到

1. 核对账号、发布者、日期和原始链接；转载指向原始发布入口。
2. 核对说话人、原话和前后文；保留条件、反例和不确定表达。
3. 区分个人主张、自述数据和独立事实。引用只能证明这里怎样表达。
4. 由编辑归纳方法时明确证据支持的范围，不从几次事件编造恒定人格。
5. 书籍、推文、访谈可能同源，不按多篇转载算多份独立验证。
6. 新观点与旧观点冲突时保留各自时间和语境，先停用有争议的条目；不要无声覆盖旧材料。

当前没有自动冲突判断。复核者在 `verification.note` 与 `application.limits` 中记录冲突，必要时把证据设成 `disputed`。模型不能把两种立场拼成一套永远正确的方法。

## X 来源

当前不抓取账号全部历史。已登记的 X 原帖通过 X 官方公开嵌入接口读取并校验帖子 ID、作者和文字；平台不返回正文时如实标记失败。也可以导入来自公开 API、合法导出或授权整理的逐帖文件：

```json
{
  "posts": [
    {
      "url": "https://x.com/<handle>/status/<post-id>",
      "author": "<handle>",
      "published_at": "2026-10-24T12:00:00Z",
      "text": "<actual public post text>"
    }
  ]
}
```

以上是占位格式，不是某人实际发过的帖子。执行 `open-mentor import-x --person naval /path/to/posts.json` 后，只写本地待审目录；不会产生已核验知识。URL 与 author 的匹配也不证明账号属于此人。人物与账号的对应需结合本人官网等材料核实。当前种子有纳瓦尔和马斯克的原帖，官站后续展开与原帖不算独立证据。

## 来源更新

`check` 抓取登记的文字页面，去除脚本等内容，计算规范化文本 SHA-256，保存本地版本。发生变化、摘录缺失或读取失败时，来源进入待复核状态，相关证据退出指导。网络失败不等于原文删除，也不丢弃旧版本。

网页更新支持 Brotli/gzip/deflate 解码、声明的HTML编码和未声明编码的旧网页；损坏或超出大小限制的响应不能接纳。PDF本轮仍为手动文本导入与复核，已登记具体文件页序；不会因格式字段存在就声称支持自动PDF解析或音频核对。

无法直接取得完整HTTP正文、但能从原发布入口读取作者正文的资料，须标为手动复核；其哈希只对应实际保存的正文摘取，不能与整个网页的自动变化检测混用。扫描PDF的OCR也只是辅助提取，所引文字需回看页面图像。原发布者声明机辅转写的采访，保留这一限制，不因原发布身份自动认定整场逐字准确。30位阶段的具体处理见[扩充审计](EXPANSION-30-AUDIT.md)。

`accept-revision` 必须指定版本与复核者，并再次检查已审阅的短摘录是否存在。接纳资料版本不证明其中的主张正确，也不提升知识条目的审阅级别。

变化检测比较页面可见文字，正文外的文字变化也可能触发复核。当前只有一个本地更新者应写入同一个 state 目录；HTTP/MCP 是只读入口。后续需要多人后台再引入数据库事务与任务队列。

## 新人物的最小贡献

先贡献一份本人文章或一个原始访谈的少量知识，提供来源、短摘录、定位、复核记录和一条明确的应用边界。运行 `open-mentor validate`。通过格式检查不等于通过内容审核。
