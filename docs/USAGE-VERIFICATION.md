# 实际提问验证

2026-10-25，使用用户原句验证：

> 帮我用OpenMentor问问孙宇晨，怎么赚自己的第一个100w

## 发现与修复

- 原检索把“自己的”等分词碎片当有效信号，只命中“按具体问题选择学习参照”，却返回 `ready`。已改为在完整虚词处断开，并过滤无意义词项。
- 原检索缺少“第一桶金/赚100w”与业务原则之间的词面联系。现在用公开、有限的主题扩展关联客户、价值、需求、试错和验证。纯扩展匹配至少需要三个实际命中词，不填满无关结果，也不把融资当个人收入。
- 人物调用语句中的“知识库、分析”等不能成为问题的匹配依据。现在先分离调用前缀与实际问题；原始请求照常保留。
- 原默认状态目录取决于当前工作目录，换目录可能丢失来源停用记录。CLI/HTTP/MCP 现在共用稳定默认路径：源码检出使用仓库 `.open-mentor/`，安装包使用 `~/.open-mentor/`；显式目录仍优先。
- 增加 `ask` / `POST /v1/ask` / MCP `ask_mentor`，允许完整自然语言请求并解析已登记人物。未指定人物时自动按可引用证据选择；多人物或请求未收录人物时返回选择状态，不静默换人。
- 每条证据提供 `citation_url`。YouTube 时码指向对应原发布版本与起始秒数；保留原登记 URL、来源日期和核验信息。

## 如何复现

```bash
.venv/bin/open-mentor ask '帮我用OpenMentor问问孙宇晨，怎么赚自己的第一个100w' --limit 3
.venv/bin/open-mentor ask '帮我用OpenMentor问问孙宇晨，怎么赚自己的第一个100w' --format json
.venv/bin/python -m unittest discover -s tests -v
```

已验证CLI、真实REST HTTP、官方MCP SDK的stdio与Streamable HTTP调用。回归覆盖不同赚钱问法、英文问法、人物别名、模糊人物选择、无关问题、调用前缀污染、来源变更停用和待核资料隔离。当前完整测试共78项，其中场景测试逐条检查298个输入；具体输入与期望见[自动选择场景](AUTO-SELECTION-CASES.md)。内容入库范围见[30位扩充审计](EXPANSION-30-AUDIT.md)，后续接口、参数与来源读取修复见[完善记录](COMPLETION-REVIEW.md)。

这不代表已向当前客户端自动登记 MCP 服务，也不代表任意模型都会正确遵守引用规则。其他 AI 客户端需按 README 接入 MCP；模型的回答仍需保留引用和推演边界。


## 不指定导师的验证

输入“用OpenMentor帮我看看，怎么赚自己的第一个100w”，当前自动选择孙宇晨，返回 `request_resolution.method=automatic_evidence_match`；显示“本次采用的导师资料：孙宇晨（自动匹配）”。选择理由连接客户价值、试错和产品需求的已复核条目。真实分析由调用的 AI 完成。

选择只代表当前已收录资料的相关性。JSON 还给出匹配主题、支持该选择的原则 ID 和最多三位候选的检索分数，分数不是人物能力、观点正确性或成功概率。扩充后改为比较每位的最强合格证据，避免多条弱命中累加占优；`--limit` 只改变展示数量。

明确指定人物时不自动换导师。自动选择前先排除待核、争议、撤回和版本变化未复核的证据；所有人都没有合格材料时返回资料不足。词项和任务约束仍是有限规则，不能声称理解所有自然语言问题。

额外发现并修复了交叉主题干扰：“作品被抄袭怎么起诉”不能拿创作观点支撑法律救济；“阅读时胸痛吃什么药”不能拿阅读习惯支撑用药；业务方法不能替代股价预测或具体方程求解。此类问题必须另有相应主题的知识证据，当前语料不足时不分配导师。服务故障“诊断”和学习数学时的失败复盘仍可正常匹配，避免仅凭一个词拦截。

## 带背景追问和实现后复查

`situation` 在 Python、CLI、HTTP、MCP 中保持同一含义：传递本轮用户事实与原问题，不保存对话。明确问题按请求检索，常见追问改用背景中的原问题检索；背景姓名不指定导师。无背景的常见追问返回 `needs_context`，来源变更和待核隔离仍然生效。

本次复查还修复了未收录导师被背景人物替代、否定指定未生效、否定调用前缀污染排名、损坏复核状态导致异常断连，以及同一次证据读取中核验结果与来源版本不一致的问题。发现、修复依据和验证范围见[改进复查记录](IMPROVEMENT-REVIEW.md)。
