# 完善与MCP验收

2026-10-25。在30位导师入库后，对检索展示、来源更新、Python/CLI/HTTP/MCP边界、接入配置和实际协议调用做了任务范围内的复查。

## 已修复的实际问题

| 问题 | 复现与影响 | 处理 |
| --- | --- | --- |
| MCP参数被SDK转换 | 真实stdio调用中，`limit=true`被当成1，`allow_secondary="true"`会开启二手资料；与Python和REST接口的要求不一致。 | 对线上原始参数先按公开Schema校验；保留原始值调用领域逻辑，不让SDK预解析改写权限式布尔参数。 |
| 可空字符串被改变 | SDK会将`person="null"`改成空值，可能从明确指定变成自动匹配；`situation="null"`也可能丢失。 | 原始字符串保持原义；明确指定未知人物正常报错。 |
| 未知MCP参数被忽略 | `persson`等拼写错误可能被忽略，让调用方误以为指定了导师。 | 参数Schema禁止额外字段，错误以`isError=true`报告。 |
| 主要工具缺少结构化结果 | 四个字典工具只返回文本，客户端需自行解析。 | 六个工具都有输出Schema和结构化结果；保留原有文本兼容。 |
| 阅读问题带金额提示 | 主题扩展产生的阅读、职业等请求也显示目标金额和期限提示。 | 仅收入问题显示这项提示，其他检索结果保持一致。 |
| 中断来源读取未停用 | gzip解压的EOFError、HTTP正文不完整的IncompleteRead可能使更新检查异常结束，而旧状态继续可用。 | 截断、损坏压缩和HTTP读取失败都写入`unavailable`并停止引用。 |
| MCP接入只有命令 | 缺少可直接生成的客户端配置和跨工作目录连通性验证。 | 增加`mcp-config`与`doctor --mcp`；使用当前虚拟环境与绝对路径，实际子进程检查。 |

MCP新增本机Streamable HTTP入口，保留默认stdio；提供只读、幂等与本地数据范围声明。搜索工具补齐显式二手资料开关，默认行为不变。缺少MCP依赖时给出安装命令，无未处理的导入堆栈。

- 孙宇晨Alan与William的机器全文仍待逐句复核；已入库原片片段与全文状态在[转写记录](TRANSCRIPTS.md)分别列明。完整机器稿不因MCP接入而变成已审定证据。

- 更新检查只处理已登记来源；自动找新材料、完整X历史、自动冲突裁决、多人写入后台和公网托管仍未实现。本轮保持单个本地更新者、只读调用接口。
